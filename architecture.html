How this starter is built

A short tour of domain-driven design, Clean Architecture, and dependency injection, using the movies app as the example. For commands, start with README.md. For agent rules, start with CLAUDE.md.

1. What this app is

The browser renders the screens. Next.js handles three server jobs: the Auth.js session, a proxy that sends guests to the sign-in page, and /api/tmdb, which attaches a server-only token and forwards movie requests. Lists and detail pages do not fetch in the server component. They call a repository through a React hook.

2. Three ideas, one feature

Domain-driven design names the things the feature talks about (TMovie, IMoviesRepository) before it names frameworks. Clean Architecture says those names must not import React or HTTP. Dependency injection is how a React hook gets a repository without constructing fetch itself. A feature is easier to copy when those three stay separate.

3. Domain-driven design

A feature is a bounded context. Movies does not know how auth stores a session, and auth does not know a poster path. Inside movies, the ubiquitous language is small: a list item, a list page, a detail, a genre. Those are types in domain/movie.types.ts. The port IMoviesRepository is the only way the rest of the feature asks for them. The domain does not mention URLs.

4. The dependency rule

app → presentation → application → domain ← data

Source code dependencies point inward, toward domain. data may import the domain (it implements the port). The domain may not import data, React, Next, TanStack Query, or openapi-fetch. application may import the port and must not import the adapter. That is why a query hook calls repo.getMovie(id) and never a path string.

Request paths live in data/movie.api-repository.ts only. Changing a path is a one-file edit plus a mapper test.

5. Dependency injection

The port is an interface. The adapter is MoviesApiRepository, marked @injectable(), with the API client injected by a Symbol token. registerMovies() binds the token to the class. useResolve(MOVIES_REPOSITORY) is the React-side lookup. The composition root is src/app/providers.tsx, which runs once on the client: core logger, toast, auth, movies, then the API client.

Constructor injection needs reflect-metadata and the two TypeScript decorator flags in tsconfig.json. src/core/di/di.test.ts fails if that metadata disappears.

6. What each layer does here

Reads skip use-cases. A use-case is for a mutation that should return a neverthrow Result instead of throwing. The base class is in src/core/domain/base/use-case.ts. This starter has no client mutation yet. Sign-in is not a client use-case: Auth.js checks the password on the server.

Repositories throw. ApiError is how a non-OK HTTP status surfaces. A 200 with results: [] is an empty list, not an error.

7. Where the files are

  • src/core/movies — the sample feature
  • src/auth — credentials, kept beside core because the proxy must import the Auth.js instance without the React barrel
  • src/core/ui — presentational only. It cannot import a feature's domain, data, or application
  • src/app — route files that render a screen and return. They do not call the movie API

8. Boot sequence

  1. Root layout injects public env and wraps the tree in Providers.
  2. Providers registers DI, then theme, session, and the query client.
  3. src/proxy.ts redirects guests to /signin and signed-in users away from that page.
  4. A screen calls a read hook. The hook resolves the repository. The repository calls openapi-fetch.

9. Auth

authenticate() accepts username admin and password admin and returns a Result. The Credentials authorize callback turns an error into null, which Auth.js reports as a failed sign-in. The form shows "Invalid username or password." The proxy has no roles and no extra unauthorized page.

10. API boundary

The browser client base URL is /api/tmdb. Generated path keys already include /3, so the base URL must not. The route handler allows GET and HEAD, adds Authorization: Bearer from TMDB_READ_ACCESS_TOKEN, and forwards to the upstream host. There is no success/data envelope to unwrap.

page → screen → useQuery → IMoviesRepository → openapi-fetch → /api/tmdb → upstream

Two kinds of types

bun run codegen runs openapi-typescript against the official movie OpenAPI document and rewrites the whole of src/core/api-client/generated/schema.ts. That file is the shared contract for every path the client can call. It is committed, and it is machine-generated: change the spec source, run codegen again, and commit the result. Do not add a type to that file by hand.

A feature's view models are a second set of types, written in domain/ (TMovieListItem, TMovieDetails). The mapper in data/ turns a generated response into those view models. Codegen does not create them, and a new screen does not append them to schema.ts.

Run codegen when the upstream document has an operation or a field the committed schema does not yet describe. If the path is already a key in schema.ts — /3/movie/now_playing, /3/movie/{movie_id}, and the rest of the published spec — the adapter imports paths and calls it. No codegen step.

11. Walkthrough: open a movie

  1. src/app/(app)/movies/[movieId]/page.tsx awaits params and renders MovieDetailScreen.
  2. The screen calls useMovie(id).
  3. The hook resolves MOVIES_REPOSITORY and runs getMovie.
  4. The adapter calls GET /3/movie/{movie_id}, and the mapper returns TMovieDetails.
  5. The screen passes poster paths through tmdbImageUrl and renders MovieHero and MovieMeta.

12. Design system

src/core/ui/primitives is stock shadcn. Authored pieces (MovieCard, AppShell, and the rest) each have a folder, an index.ts, a .md, a test, and a story. Screens have tests and a .agents.md file, not stories. The shell is a header, not a sidebar.

13. What is enforced

  • ESLint blocks deep imports such as @/core/movies/domain/… and path segments like v1 or old.
  • src/proxy.ts and src/app/api/auth may import @/auth/data/auth so the client barrel stays out of the proxy.
  • bun run depcruise checks the layer arrows.
  • Outside a feature, import @/core/movies or @/auth only.

14. How to add a feature

  1. Create src/core/<feature>/ with domain, data, application, presentation, and di.
  2. Write the port and view models first. No framework imports.
  3. If the upstream OpenAPI document has operations the committed schema.ts does not list yet, run bun run codegen and commit the regenerated file. A path that is already in that file needs no codegen run. Write the feature's own view models in domain/ either way.
  4. Implement the adapter and mapper. The adapter calls a path from paths. The mapper returns the domain view model. Put the path in the adapter only.
  5. Add a read hook and a query key. Export the public surface from index.ts.
  6. Call register<Feature>() from providers.tsx.
  7. Add a thin page.tsx that renders the screen.
  8. Add <feature>.md, a .md and story and test per UI component, and a .agents.md per screen.
  9. Extend the ESLint façade pattern and the dependency-cruiser UI rule so the new feature cannot be deep-imported and core/ui cannot import its business layers.
